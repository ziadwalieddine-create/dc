# Requirements and verification

Generated by `variant_index/check_requirements.py` from `requirements.json` (edit that file, not this one). Each clause of the project goal is mapped to the code that implements it, the test modules that exercise it and a status. The script verifies that every path and test module named here exists; that the tests pass is shown by running `python3 -m unittest discover` in `variant_index/tests`, and the numbers of a particular build and run are in `STATUS.md` and `BUILD_REPORT.md`.

## Status vocabulary

- `verified`: implemented, and exercised by the named tests (adversarial fixtures) and, where stated, by a real-data run
- `partial`: implemented for part of the clause; the gap field says what is missing
- `not_implemented`: no code; the gap field says what would be needed
- `not_acquired`: the data are not in the environment; the gap field says why
- `unavailable_input`: the clause needs an input that does not exist in this environment
- `blocked_external`: only a person outside this session can satisfy it

**E1.** Every evidence row carries release_id, accession, locator and the SHA-256 of the raw record text. provenance.verify_index re-opens the acquired files, recomputes the digests of a deterministic sample per release and checks release linkage and manifest agreement. *Gap:* Digest recomputation has resolvers for the ClinVar VCF and VCV tables, GWAS Catalog, gnomAD and the Ensembl MaveDB file and the ClinGen export; releases without a resolver are listed as such, not counted as verified.

**E2.** Variants have one normalised key; xref carries rsIDs and database identifiers; evidence ids are deterministic hashes, so a record seen twice is one row.

**E3.** mapping_status mapped / ambiguous / unmapped / rejected with a reason; effect_assertion effect / no_effect / uncertain / conflicting / not_applicable; lineage_group on every row.

**E4.** Rows that descend from one study share a lineage_group (for example pmid:<PMID> across GWAS Catalog, Open Targets and ClinVar); the per-axis summary counts independent lineages, not rows.

**E9.** Molecular, functional and clinical claims sit on different axes and claim types. A variant with no row for an axis has no assertion on that axis; no_effect is only written for an explicit negative record, and the matcher reports NO_INDEX_RECORD / ABSENT_FROM_CALLSET instead of a negative.

**M1.** vcfio reads VCF / gVCF (small alleles, symbolic SV / CNV alleles, repeat genotypes, reference blocks) and wgs.run_sample matches a whole file one contig at a time, then once more for every record off the primary assembly. *Gap:* No personal 30x callset exists in this environment. The pipeline is verified on synthetic fixtures and on the public GIAB HG002 benchmark callset (not anyone's personal genome).

**M2.** Normalisation is cross-checked against bcftools norm (random variants in the tests, and a whole-run comparison of calls and evidence matches); PGS scoring is cross-checked against plink2; star alleles come from the CPIC and PharmVar definitions. *Gap:* The star-allele caller is this repository's own implementation of the published definitions; structural genes (CYP2D6, HLA, KIR) need a dedicated caller (Cyrius, Aldy, StellarPGx, PharmCAT) whose result is supplied with --external-haplotypes. None is installed here.

**M3.** assembly_check compares the VCF header contigs with the reference (build guess from the chr1 length); AssemblyMismatch stops a run unless explicitly overridden; every REF allele is checked against the FASTA and a mismatch is rejected and listed.

**M4.** Each split allele carries its own dosage, ploidy, phase and phase set, GQ, DP, allele depth, QUAL and filter; QC flags are recorded, not applied silently.

**M5.** Matching is by key only. GWAS rows whose strand cannot be resolved (palindromic or multiallelic sites) are rejected with the reason; effect and other alleles are stored with the row.

**M6.** MaveDB protein-level variants are mapped to genomic alleles only when the codon change is determined; otherwise they are ambiguous rows that list the candidate alleles.

**M7.** match_sv requires compatible type, reciprocal overlap, breakpoint agreement within the stated uncertainty and, where the index states a copy number, the same dosage; near-misses are returned with the reason they were refused.

**M8.** match_hap resolves a diplotype only when every defining position has a confident genotype (phase or an unambiguous diplotype) and otherwise says which positions are missing; match_repeat classifies only repeat sizes reported by a repeat genotyper, and keeps every repeat genotype of the file (NO_INDEX_RECORD when the index has no locus or threshold for it). *Gap:* Repeat lengths are not estimated from short reads; without ExpansionHunter / TRGT output the repeat loci are reported as unresolved.

**M9.** Statuses EXACT_MATCH, FILTERED_CALL, NO_INDEX_RECORD for calls; VERIFIED_REFERENCE, NO_CALL, ABSENT_FROM_CALLSET, OTHER_ALLELE_AT_SITE, DELETED_BY_UPSTREAM, UNRESOLVED for indexed loci, each with its basis.

**M10.** Reference is established only by gVCF blocks, a declared callable-region mask (with the all-variants assumption recorded in the basis) or read pileup; otherwise the locus is ABSENT_FROM_CALLSET with the exact missing evidence.

**M11.** match_wgs.py and score_pgs.py refuse an output directory inside the tracked tree; .gitignore blocks VCF / BAM / CRAM / FASTQ files anywhere; matching is a local bulk join and never queries an external service per variant; check_repo_policy.py scans for personal-genome file types.

**D1.** build_index.py builds the Parquet index (13 tables, schema in SCHEMA.md) from the acquired sources into data/index, always from an empty directory, with per-table digests.
