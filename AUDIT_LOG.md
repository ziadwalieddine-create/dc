### Findings that changed earlier conclusions
1. **Superseded score sets were missed.** The MaveDB search (used to build the human set) omits superseded versions. The CC0 bulk dump v4 (asOf 2026-06-24) lists 52 published score sets absent from the search listing; the API serves all of them (HTTP 200, flagged superseded). 51 have a human or accession target. They are kept as an additive, labelled extension in `acquisition/mavedb_superseded/` (79 tables, all row counts equal to `numVariants`). The statistics endpoints (2,995 sets; 1,617 human targets) are consistent with 2,938 + 52 hidden + about 5 non-CC0 hidden sets, and 1,477 + 84 + 51 + about 5 targets. Consistent, not proven.
2. **The MaveDB bulk dump is much richer than assumed.** Besides scores and counts it provides per-variant annotations (MaveDB-mapped genomic/coding/protein HGVS, VRS digest, VEP consequence, gnomAD v4.1 allele frequency, ClinGen Allele Registry ID, historical ClinVar significance), mapped-variant JSON and GA4GH VA-Spec annotations. Of those, `main.json` and the 1,170 annotation CSVs (708 MB) were extracted; the 9.5 GB `mapped/` and 3.4 GB `va/` files were left in the archive.
3. **Two mapping products are complementary, not interchangeable.** Ensembl's VEP MaveDB file expands protein-level variants into every codon-compatible genomic allele; MaveDB's mapper gives genomic HGVS only to nucleotide-level assay variants. A one-to-one concordance test was the wrong test and was replaced by a recorded finding.
4. **Existing tables equal the dump.** On a sample of 31 of our sets the dump's scores are identical to the API-built tables (same rows, accessions and values).
5. **Ensembl release 116 already ships VEP plugin data** (MaveDB, LOEUF, SpliceAI, SpliceVault, ProtVar, mutfunc, Enformer and others). They are catalogued; only the MaveDB file was acquired.
6. **Open Targets 26.09 already integrates** credible sets, colocalisation, locus-to-gene, ClinGen, ClinVar (EVA), IMPC, CRISPR screens, DepMap essentiality, gene burden, pharmacogenomics and interactions (61 datasets from the FTP listing). Adopted as the primary route for those dimensions; none downloaded yet.

### Corrections and mistakes found during this phase
1. The first regional reference reads covered only the 25 standard sequences, and the validator looked for a `.fai` in a cache directory that was empty (htslib keeps a remote index in memory and saves none). The `.fai` check failed, which exposed that the check "every region lies inside its sequence" would have passed vacuously. Now the `.fai` is saved explicitly (length checked against Content-Length), all 54 sequences are read, and a region on an unknown sequence counts as a failure.
2. The GTF validator's first rule, "every complete protein_coding transcript has a CDS length divisible by 3", was wrong: 44 of 253,709 transcripts break it. Inspection: 31 carry `mRNA_end_NF` (the transcript end is incomplete), 6 are mitochondrial (stop codons completed by polyadenylation), and 7 have no incompleteness tag (ENST00000434431 = TMEM247-201, the MANE Select transcript, which has no stop_codon feature; MLH1-203; NOL6-204; IL11RA-212, -241, -247; CCDC178-203). The rule now excludes the documented groups and tolerates at most 0.01% of the 253,244 remaining transcripts (7 observed, 0.003%); the 7 identifiers are kept in the validation report. The non-coding-gene biotypes `protein_coding_LoF` (31), `non_stop_decay` (43) and `nonsense_mediated_decay` (9) also have off-frame CDS and are reported, not tested.
3. My first profile of the SIFTS files used text mode with universal newlines and so hid that `pdb_chain_uniprot.tsv.gz` has CRLF line endings on every data line while `uniprot_segments_observed.tsv.gz` uses LF. The validator (which reads with newline='') exposed it; every reader here strips `\r\n`. Also found in the data, and counted rather than rejected: 78 segments with reversed UniProt ranges (engineered constructs, for example 1cu1 and the HIV-1 protease entries 1g6l and 3n3i), and 23,251 segments whose SEQRES and UniProt lengths differ (internal deletions in the construct).
4. Two thresholds in the new PharmVar tests were guessed instead of derived (more than 10,000 distinct defining substitutions and more than 10,000 checked rows) and failed on the first full run although every row agreed (1,756 distinct alleles; 9,553 checked rows). The first now has no pass criterion (a relationship finding) and the second requires that every row is classified and checked and that all reference alleles agree.
5. `acquire.py` named `fetch_gnomad_regional.py` as the writer of every regional-slice target; targets can now name their writer (`written_by`).
6. The catalogue still pointed to the guessed PharmVar terms URL as evidence; the source record now cites only the page that was read.

### Defects found by verification and fixed (each has a test that fails without the fix)
Found by row-accounting tests, adversarial fixtures, independent re-parsing of the sources (bcftools, the raw files), value sweeps over the real outputs, the scale runs, and by reading the output tables and the requirement texts the way a user would; apart from the two named as such (a scale risk found by reading the code, a question about who carries two copies of an effect allele), none was found by reading the code alone.

- **Rows lost silently.** The row-accounting test showed Arrow dataset discovery skipping folders whose names start with an underscore. 137 mapped ClinVar variants on alternate loci and scaffolds were filed in the shared `NA` partition, never became entities, and a matcher asking for them found nothing; the whole-file runner read only the primary contigs. One partition rule (`schema.partition_of`) now serves writer, reader, entity builder, validator and runner, and contigs off the primary assembly are matched or listed as `contig_unmapped`.
- **Calls dropped or wrongly matched.** A symbolic SV with genotype 0/0 could be reported as an equivalent event (now listed with `genotype_is_homozygous_reference`, nothing linked); repeat genotypes at loci the index does not know were dropped (now `NO_INDEX_RECORD`); a confidence interval of `.` counted as an interval; unresolved statuses had empty `missing_evidence` (a test now reads the matcher source and fails when a status states none).

  - ClinPGx: nine odds, hazard or risk ratios that were zero or negative (a beta typed into the ratio column) kept as ratios; eighteen p-values printed as `0.000`; intervals with start above stop. A `pkill -f` pattern that matched the command line of the shell that issued it stopped that command before it had done anything, and was replaced by a bracketed `pgrep` pattern.

14. **The container was restarted during the second attempt.** At 23:30, 105 minutes into the restarted build (2.5 GB written, in the Open Targets stage), the container running the session was restarted; the build and every background job died, the files on disk (data, scratch directory, repository) survived, and the build was started a third time at 23:34. A build is not resumable (the writers of all adapters stay open until the end), so each interruption costs the whole run; the idempotence check, which ran on the same build code, was not repeated.

## 2026-10-28 (sixth phase): read-level evidence, ontology cross-references, every evidence row re-derived

This entry supersedes the fifth-phase entry wherever they differ, in particular its "Not implemented" and "Unresolved" sections on read-level evidence, the trait roll-up and the size of the provenance sample.

### Added
- **`vindex/reads.py`** and `match_wgs.py --reads` (`--reads-index`, `--read-min-*`): for the small variants a callset leaves unresolved, the fragments of an indexed BAM or CRAM that carry the reference, the indexed alternate or another sequence over a window are counted. The window covers the whole repeat tract of an insertion or a deletion, so a gap the aligner put at the other end of a repeat still gives the allele; filters for mapping and base quality and for flagged duplicates, one count per fragment, caveats that forbid reading the absence of alternate fragments as reference. Six states (`READS_ALTERNATE_PRESENT`, `_OTHER_ALLELE_PRESENT`, `_REFERENCE_ONLY`, `_AMBIGUOUS`, `_INSUFFICIENT`, `_NOT_EVALUATED`) are written beside the matcher's status in `unresolved_loci` (`read_*` columns, `read_settles`), never over it; the run manifest records the alignment, its assembly check, the policy and the cross-tab of status by read state; the report has a section for them. It tests the presence of an allele and is not a genotyper. A CRAM is decoded against the project's bgzip FASTA.
- **`validate_reads.py`**, `reads_validation.json` and a gap-audit check: the resolver against the GIAB HG002 benchmark on the public Illumina reads of HG002 (GIAB, Novoalign, GRCh38, about 60x), read over HTTPS, at 60x, 30x and 15x (the same fragments thinned by a hash of the read name); 2,200 loci per depth, fixed seed, reproducible (the 60x run was made twice and gave identical states).
- **Trait roll-up through cross-references** (`views.trait_rollup`): ids the Open Targets ontology table does not hold are placed through the terms that list them as cross-references or replace them (retired terms), the mapping is kept and many-to-one cases are flagged; the prefix is part of the match.
- **Provenance of every evidence row**: `provenance.verify_release` re-opens the records in chunks (a first attempt that held the sample of the largest release in memory was killed by the container's out-of-memory killer at 10.7 GB), so that the digest of every evidence row can be recomputed; the report names the code that made it. `verify_index.py` samples up to 50,000 rows per release by default.
- Tests: 557 in all (new: `test_reads` 49, `test_reads_run` 11, `test_rollup` 10, five in `test_provenance`; `tests/bamfix.py` writes synthetic alignments). Mutation checks: 36 mutations of `vindex/reads.py` and 12 of the roll-up, all caught (two that survived the first version of the tests led to two more tests).

### Findings of the verification
- **What real reads showed that fixtures could not.** Against the benchmark, reads read the reference allele at 996 of 1,000 random absent alleles and never read one as carried; at the benchmark's alleles 97.6% (heterozygous) and 97.5% (homozygous) of 1,200 are read as carried at 60x, 96.1% and 96.8% at 30x, 87.0% and 94.8% at 15x (the rest abstained or are the contradictions below). 16 of 2,183 claims at 60x contradict the benchmark: 15 alleles whose window, in the reads, is neither the reference's nor the indexed allele's (14 of them have another benchmark variant of the same haplotype inside the window: an insertion and a neighbouring SNV are two records of the benchmark, one haplotype in the reads), and one heterozygous 5-base insertion that no read of the alignment shows. The comparison of whole windows cannot tell "another allele" from "the indexed allele with another variant beside it"; the state says only what was seen and keeps the sequences, and the wording of its interpretation was changed from "a different allele" to "another sequence over the window" after this was found.
- **A base-quality rule that costs depth.** Requiring every base of a window of 20 or more bases to pass `min_baseq` removes many reads of this alignment in long windows; it never produced a wrong claim and it is why a few loci at 30x and 15x abstain. The rule is kept and stated; the reasons of an insufficient locus now say when most alignments fail it or do not span the window.
- **Output that could mislead.** The documents said that no read-level provider exists (README, STATUS, the module registry, a docstring, requirement M10) and that no mapping between ontologies is made (requirement D3); both were rewritten with what now exists and what does not. The sample-run report lists a trait by the texts that co-occur with its id in evidence rows (the first two in alphabetical order), which are not always its label; this is listed among the residuals, not changed here.

### Corrections and mistakes found during this phase
1. **A fixture error read as a resolver error.** The first end-to-end fixture put the reads of two loci 20 bases apart on each other's positions (depth 30 instead of 14); the resolver was right and the fixture was wrong.
2. **Test isolation.** A helper wrote `sample.vcf.gz` into a directory shared by tests, so a later test read another file; a test method named `run` shadowed `unittest.TestCase.run`. Both fixed; neither was a defect of the code under test.
3. **Wrong expectations in my own tests.** The number of equivalent placements of a two-base deletion in a (GT) repeat (ten, not nine) and the reason a window-limit refusal gives were written from memory; the data and the code were right.
4. **Two mutations survived the first tests** (the minimum number of alternate fragments, and the guard that a contig of another length is never used); two tests were added.
5. **A documentation edit changed a digest.** A docstring edit of `vindex/__init__.py` would have changed the build-code digest of the index (the digest covers that file) and made the index look older than HEAD; two skipped tests showed it and the edit was reverted.
6. **A validation run lost loci to the network.** The 30x run was made while the machine was also running the provenance check, and 23 loci failed to read (htslib seek errors, states `ERROR`, never counted as evidence); the validator now reopens its handle after a failed read, a 15x run begun with the old script was stopped, and both runs were repeated alone.
7. **A full provenance run was killed by the container.** See above (10.7 GB); the check is chunked now.
